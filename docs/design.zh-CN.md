# LLM 伪造用户话语的双层防护方案

## 问题

某些长对话或工具调用场景中，模型可能在 assistant 输出末尾继续生成一段并不存在的用户话语。更危险的是，这段伪造内容进入 transcript 后，模型下一轮可能把它当成真实历史，继续引用、解释，甚至据此行动。

另一种更隐蔽的变体发生在 reasoning/thinking 中：模型明确写出“用户刚才问了 X”，但用户实际上从未说过 X。

## 双层设计

```text
assistant 输出
    │
    ├─ 第一层：输出截断
    │   识别结构异常，从异常位置截断，避免伪造用户话语展示给用户
    │
    └─ 第二层：下一轮事实纠偏
        用户再次发言时，检查上一条 assistant 的错误归因
        对照此前真实用户消息，发现不存在则注入纠偏上下文
```

第一层保护用户界面，第二层防止模型把自己的幻觉继续当成事实。

## 第一层：结构性截断

扫描 assistant 可见文本末尾的有限窗口，跳过 Markdown 围栏代码块，仅在行首或整行精确匹配以下特征时截断：

- 单独一行的 `user`、`assistant`、`human:`、`h:`、`a:`
- 带角色前缀的秒级对话时间戳，包括 `user[...]`、`univers[...]` 一类受损角色前缀
- 行首出现 `mid-stream interruption` 一类内部协议残片

默认窗口为末尾 40 行且不超过 4,000 字符。没有角色边界的裸时间戳按普通日志处理，避免截断合法日志输出。

截掉的内容应由接入方写入权限受限、定期轮转的本地审计日志，不能展示给用户。本库自身不保存对话正文。

## 第二层：语义错误归因检测

在下一次用户消息进入时，读取上一条 assistant 的正文；平台允许时也读取 reasoning/thinking。只寻找带引号的近邻归因，例如：

```text
用户刚才说“……”
她刚刚问“……”
上一条用户发了“……”
```

把引号内逐字内容与该 assistant 事件之前的真实用户消息比对。查无时注入只含异常类型、数量和位置的纠偏上下文，不回填可疑原文，也不修改 transcript。

## 真实用户消息过滤

不能把所有 `role=user` 都视为真人输入。以下事件必须排除：

- tool result
- 命令输出
- system reminder
- heartbeat 或定时任务
- XML/标签式上下文注入
- memory retrieval 结果

只查询 assistant 事件之前的用户消息。用户事后说“我没有说过 X”时，这条纠错消息本身含有 X，绝不能反过来给此前幻觉作证。

## 精度策略

- 只检查带引号的逐字归因
- 只抓“刚才、刚刚、上一条、主动、直接”等近邻描述
- 不判断无引号释义
- 不检查远期记忆归因
- 排除“如果用户刚才说……”一类假设句
- 只归一化空白，不做模糊语义匹配

目标是低误报，不是覆盖所有幻觉。

## 方案边界

- 第一层只能拦截带结构特征的伪造轮次
- 第二层主要防止下一轮继续相信幻觉
- 当轮已经基于 reasoning 幻觉生成的第一条回复未必能及时阻止
- 平台不提供 reasoning 时只能检查可见正文
- 这不是通用事实核验器
